## A. 购买物流服务的用户 · Customer / end buyer

### IT-TC-001 — Sign in with each role account

| Field | Value |
| :--- | :--- |
| Priority | P1 |
| Role | All three roles + built-in `demo` |
| Preconditions | Dataset loaded; backend running; `users` 101–107 exist |

Requests (repeat for each account):

```http
POST /api/auth/login
Content-Type: application/json

{"username": "it_customer_amy", "password": "It@2026Test"}
```

Account matrix:

| username | password | expected `user.id` | expected `user.role` |
| :--- | :--- | :---: | :--- |
| `it_customer_amy` | `It@2026Test` | 101 | `customer` |
| `it_merchant_ken` | `It@2026Test` | 103 | `warehouse_admin` |
| `it_driver_dan` | `It@2026Test` | 105 | `courier` |
| `demo` | `demo123` | startup-assigned | `admin` |

**Expected:** `200`, body has `token` (non-empty), `token_type = "Bearer"`, and
`user = {id, username, role}` with no `phone` or `password_hash` field.
**Negative control:** `{"username":"it_customer_amy","password":"wrong-password"}`
must return `401 {"error":"invalid credentials"}`.
**Cleanup:** none (tokens are process-local).

### IT-TC-017 — Data survives a backend restart

| Field | Value |
| :--- | :--- |
| Priority | P0 |
| Role | Customer (re-login after restart) |
| Preconditions | IT-TC-001 … 006 executed on a disposable `LMS_DB_PATH` |

acceptance criterion in `docs/PROJECT.md` (TASK-python-sqlite-integration).
**Cleanup:** none.

### IT-TC-003 — Create a waybill with atomic stock deduction

| Field | Value |
| :--- | :--- |

with trigger-filled `unit_price = 150.00`; exactly one new `pending`
`tracking_events` row with `hub_id = NULL` and description
`Shipping order created by sender.`; shipment count +1. Reloading does not
deduct stock twice. Aligns with manual case TC-002.
**Cleanup:** reload file 04 (or run on a fresh disposable DB).

### IT-TC-018 — Duplicate order line rejected by the UNIQUE constraint

| Field | Value |
| :--- | :--- |
| Priority | P2 |
| Role | Merchant / database integrity |
| Preconditions | `shipment_items` 102 = `(102, 102)` exists |

Attempt (in a scratch transaction, **not** through the API):

```sql
INSERT INTO shipment_items (shipment_id, item_id, quantity)
VALUES (102, 102, 1);
```

**Expected:** `sqlite3.IntegrityError: UNIQUE constraint failed:
shipment_items.shipment_id, shipment_items.item_id`. Roll back the transaction.
This documents the v1.2 guard that prevents one SKU being booked twice in an
order. **Cleanup:** `ROLLBACK`.

## C. 运送货物的司机 · Driver / courier

### IT-TC-004 — Status flow pending → shipped → delivered

| Field | Value |
| :--- | :--- |
| Priority | P0 |
| Role | Driver (`it_driver_dan`, id 105) |
| Preconditions | IT-TC-001 token; `IT-2026-0001` (`shipment_id` 101) is `pending` |

```http
PATCH /api/shipments/101/status
Authorization: Bearer <token>
Content-Type: application/json

{"status": "shipped"}
```

Then repeat with `{"status": "delivered"}`.

**Expected:** each call returns `200` with the updated `status` and a refreshed
`updated_at`; each appends exactly one `tracking_events` row with
`hub_id = NULL`, matching `status`, and description
`Shipment status updated to shipped.` / `... delivered.`. Stock is **not**
deducted again. `IT-WM-101` remains 120 (or 118 if IT-TC-003 ran first). Aligns
with manual case TC-003. **Cleanup:** reload file 04.

> Note: the API validates only the enum; it does **not** enforce transition
> order. A reverse change (`delivered → pending`) is currently accepted. Do not
> assert rejection — see assumption A-04.

## D. Cross-cutting negative controls

### IT-TC-012 — Writes require authentication

| Field | Value |
| :--- | :--- |
| Priority | P0 |
| Role | All (unauthenticated probe) |

Send `POST /api/shipments`, `PATCH /api/shipments/101/status` and
`POST /api/shipments/101/events` **without** `Authorization`, and once with an
invalid token.

**Expected:** `401 {"error":"valid bearer token is required"}` with
`WWW-Authenticate: Bearer`; no data changes. `GET /api/health`, `/api/items` and
`/api/shipments` remain public (`200`).
